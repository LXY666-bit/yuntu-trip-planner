# Agent 规划可靠性与对话编辑

本次升级围绕一个可验证的闭环：程序发现冲突 → 模型提出受限修改 → 程序复验 → 用户确认 → 原子保存。模型可以选择候选景点和开始时间，不能自行写数据库或修改酒店。

## 使用入口

正常生成草稿后，在草稿页顶部：

1. 展开“设置必去景点、时间和预算”，填写要求并保存。必去景点目前按精确名称匹配，使用景点卡片的名称。
2. 点击“检查行程”。硬约束冲突阻止定稿；信息缺失显示“待核实”，不会伪装成已验证事实。
3. 点击“尝试修复冲突”，或输入“第二天下雨，换成室内景点，酒店和第三天保持不变”。日期不明确时可在下拉框选择。
4. 阅读修改前后景点、开始时间、总预算与校验提示。点击“确认应用修改”才更新草稿，“保留原行程”取消建议。
5. 需要记录偏好时，主动勾选“记住这次选择的景点类型”。默认不记录。

对话编辑支持单日景点替换、排序和开始时间。酒店、餐饮和其他日期保留；受影响日期重新计算路线和预算。普通问答接口仍可回答问题，写操作统一通过草稿提案接口。

## 核心实现

| 层次 | 实现与保证 |
| --- | --- |
| 数据约束 | Pydantic 限制日期、时间、天数、预算和 patch 字段；候选 ID 白名单拒绝编造或重复景点 |
| 确定性校验 | 必去景点遗漏、重复日期/景点、日期和时间轴一致性、简单开放窗口、游览加交通加餐饮时长、最晚结束、预算 |
| 信息边界 | 未知营业时间、未知价格、估算路线、跨城交通未核验、缺少 POI/坐标均单独提示 |
| 有限修复 | 每次最多两轮、最多五个受影响日期；总截止 180 秒，候选检索 25 秒、单次模型和路线 35 秒 |
| 提案保存 | 持久化 before/after、校验报告和原草稿快照；一小时有效，草稿发生变化后旧提案拒绝应用 |
| 确认应用 | 再校验后以 CAS 写入变更日期，重复确认已应用提案返回已应用状态；偏好与草稿同事务保存 |
| 并发可靠性 | 不同日期编辑合并重试，同日期过期编辑返回 409；定稿状态与历史记录同事务保存 |
| 流式可靠性 | 生成期间持续心跳；前端未收到 complete 就 EOF 会报错；取消时释放迭代器任务 |

新增数据库表 `plan_proposals` 由启动时 `create_all` 创建。既有表不删改；新增请求/详情字段使用兼容默认值。旧草稿不具备价格来源时会提示待核实。

预算暂按门票和餐饮乘同行人数、住宿按两人一间向上取整、末日不住宿、交通每人每天 50 元计算。门票区分 verified/estimated/unknown，只有有证据的数据才能标为 verified；当前抓取/模型提供的价格通常是 estimated。总额始终是估算；未知费用单列，不作为免费项目。跨城车票与机票尚未纳入可靠报价，不能把校验通过解释为可直接订购。

营业时间只解析简单时段与明确的当日闭馆，预约、旺淡季、节假日等复杂规则提示人工核实；室内筛选优先使用候选字段，缺少字段时仅使用博物馆等保守名称规则。POI 可核验率衡量 ID 与合法坐标齐备程度，不能证明对应实体或开放状态已实时验证。

## API

以下路径均以 `/api/trip/draft/{draft_id}` 为前缀。

| 方法与路径 | 用途 |
| --- | --- |
| GET `/validation` | 当前草稿规则报告 |
| PUT `/constraints` | 保存 must_visit、max_day_minutes、day_end_time、budget |
| POST `/proposals` | `{message, day_index?, repair}` 生成建议；day_index 从 0 开始 |
| GET `/proposals/{id}` | 读取已保存的建议 |
| POST `/proposals/{id}/confirm` | 必须传 `{confirmed: true, remember_preferences: false}` |
| DELETE `/proposals/{id}` | 取消尚未应用的建议 |

不支持的请求返回 422，草稿变更或提案过期返回 409，资源缺失返回 404。提案 `blocked` 表示没有得到可应用方案，保留原行程并报告原因。停止生成会取消客户端等待，服务端仍可能运行至总截止；它最多保存一个未确认建议，不会自行修改行程。

## 运行指标

API 响应返回 `X-Run-ID`；后端默认追加 `data/run_metrics.jsonl`，不记录提示词、密钥或模型思维内容。记录逻辑 LLM/工具调用数、封装层重试数、token、总耗时、SSE 首个可用事件时间、节点耗时及部分降级信号。SDK 内部隐式重试不在逻辑计数内；首个可用事件可能是景点，不能直接当作首次可编辑草稿耗时。评测脚本另记 `first_editable_ms`。

通过进程环境变量 `RUN_METRICS_PATH` 自定义路径；设置 `LLM_INPUT_CNY_PER_MILLION` 和 `LLM_OUTPUT_CNY_PER_MILLION` 后估算人民币 token 成本。未配置价格或供应商未返回用量时为 null；不同模型/缓存计费不同，当前统一费率只作参考，不代替账单。部署时自行配置日志轮转和保留时间。

## 无 API 调用的演示

在已安装项目依赖的环境运行以下命令。演示使用临时数据库、固定候选/路线/模型回复，不触碰正式行程数据；不要用它验证真实模型表现。

后端终端（从项目根目录）：

```powershell
cd backend
python scripts/demo_upgrade.py
```

前端另一个终端（从项目根目录）：

```powershell
cd frontend
$env:VITE_API_BASE_URL=''
$env:VITE_BACKEND_URL='http://127.0.0.1:18001'
npm run dev -- --host 127.0.0.1 --port 15173
```

访问 `http://127.0.0.1:15173/draft/<后端输出的ID>`。ID 也写入 `backend/evals/results/demo-id.txt`。输入第二天改室内的示例，可观察到只有第二天由演示公园变为演示博物馆；再将预算设为 1 元，修复会返回不可应用结果。最后恢复预算 2000 元，可以定稿查看结果。演示禁止图片检索、普通问答等未提供固定响应的入口，避免意外访问真实服务。

## 验证与面试展示

后端 `python -m pytest -q`；前端 `npm test` 与 `npm run build`。新增回归覆盖并行节点同时失败、SSE 断流/心跳、并发编辑、定稿事务、伪造候选、两轮上限、明确确认、过期/取消提案、其他日期和酒店不变，以及 30 个固定案例。离线评测命令见 [评测说明](../backend/evals/README.md)。

展示时可以从失败案例讲起：原计划在闭馆时间安排景点，规则输出具体冲突；模型只选择候选，程序复验；不可满足时保留原行程；确认成功后只修改目标日期。测试和合成评测说明工程机制有效，真实模型效果、成本和服务可用性需要另做 live 与 smoke 验证。

本项目仍沿用原有个人项目身份机制，没有增加多租户鉴权。大规模上线还需完整身份授权、审计保留策略及生产数据库迁移机制。
